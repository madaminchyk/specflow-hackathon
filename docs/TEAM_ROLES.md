# План распределения работы команды

Это предлагаемые зоны доработки и защиты, а не утверждение об уже выполненном индивидуальном вкладе. Замените «Участник 1–5» реальными именами. Реальные изменения оформляйте собственными коммитами, не подделывайте историю.

| Участник   | Зона                  | Файлы                                                                              | Проверяемый результат                                                        |
| ---------- | --------------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Участник 1 | Product / аналитика   | `src/data/demo.ts`, `src/domain/model.ts`, `docs/DEMO_SCRIPT.md`, `docs/RUBRIC.md` | Проверены точные источники; согласован объём; подготовлены ответы о ценности |
| Участник 2 | Frontend / UX         | `src/app`, `src/features`, `src/styles`                                            | Рабочее пространство и клавиатурная навигация на 360/768/1440                |
| Участник 3 | AI / backend          | `server`, `api`, `.env.example`                                                    | Реальная интеграция на тестовом ключе, валидация, безопасные ошибки          |
| Участник 4 | Data / export / QA    | `src/services`, `tests`                                                            | Сохранение, восстановление, корректные экспорты, отчёты тестов               |
| Участник 5 | DevOps / демонстрация | `.github/workflows`, `docs/DEPLOY.md`, README, `docs/PITCH.md`                     | Сборка CI, публикация командой, резервный офлайн-сценарий                    |

Перед защитой каждый участник проходит весь демонстрационный сценарий и может объяснить свою границу ответственности. Участники 1 и 3 отдельно проверяют AI-предложения; участники 2 и 4 проверяют UX на телефоне; участник 5 отвечает за финальный воспроизводимый запуск.
