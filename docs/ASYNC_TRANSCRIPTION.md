# Длинные записи: контракт и следующий этап

Сейчас реализован только синхронный SpeechKit v1: WAV PCM 16-bit mono (8/16/48 кГц) или OggOpus mono, до 30 секунд и 1 000 000 байт. Это ограничение проверяется на сервере перед внешним запросом. Размер проверяется также в браузере. Никакой автоматической обрезки, разбиения, генерации демоданных или очереди в памяти нет.

`POST /api/transcribe` с `{ "mode": "async" }` возвращает HTTP 501 и `{ "code": "ASYNC_NOT_CONFIGURED", "error": "…" }`. Идентификатор задачи не создаётся. Превышение лимита синхронного режима даёт HTTP 413 и `ASYNC_REQUIRED`. Интерфейс объясняет ограничение и предлагает добавить готовую транскрипцию или отдельный короткий фрагмент. Это не включается переменной окружения.

## Уже подготовлено

В `src/domain/transcription.ts` определены публичные возможности режима, коды ошибок и интерфейс будущего адаптера:

```ts
interface AsyncTranscriptionProvider {
  submit(
    input: { objectKey: string; requestId: string },
    signal?: AbortSignal,
  ): Promise<TranscriptionJob>;
  get(jobId: string, signal?: AbortSignal): Promise<TranscriptionJob>;
}
```

`TranscriptionJob` различает `queued`, `running`, `completed` с нормализованными сегментами и `failed` с безопасной ошибкой. Клиенту не требуется знать API-ключ, идентификатор операции провайдера или внутренний адрес хранилища. Сейчас нет реализации этого интерфейса и endpoint для polling.

## Что нужно реализовать для запуска

1. Авторизация и принадлежность проектов пользователям; серверная БД задач с устойчивыми состояниями. Привязать `requestId` к владельцу и содержимому, обеспечить идемпотентность повторной отправки.
2. Прямая загрузка в закрытый Yandex Object Storage по ограниченному временному разрешению. Сервер выдаёт и проверяет `objectKey`, права владельца и фактический размер/формат объекта. Не принимать произвольные внешние URL от клиента.
3. Worker вызывает асинхронный SpeechKit, сохраняет ID операции в БД и опрашивает реальный статус с ограниченными повторами и задержкой. Перезапуск worker не теряет работу и не создаёт повторное платное задание.
4. Получать результат и нормализовать сегменты; использовать точные таймкоды только если они присутствуют в ответе. Сохранить транскрипцию до анализа требований и проверять версию проекта перед применением результата.
5. Добавить endpoint статуса с проверкой владельца, возобновление ожидания после перезагрузки UI, ошибки, срок хранения и удаление аудио. Процент выполнения показывать только при наличии достоверного значения от провайдера; иначе — фактическое состояние задачи.
6. Разделить отмену ожидания клиентом и отмену работы провайдера. Проверить дубликаты, таймауты, перезапуск worker, отказ Object Storage, истёкшие права и потерю соединения mock-тестами; отдельно провести разрешённую проверку на реальном коротком файле.

Выбор версии async API, региональных endpoint, ролей доступа и параметров производится при подключении инфраструктуры по [документации асинхронного распознавания SpeechKit](https://aistudio.yandex.ru/ru/docs/speechkit/stt/transcribation). Наличие контракта не означает доступность обработки длинных записей в текущем приложении.
