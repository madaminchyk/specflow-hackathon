# SpecFlow — из разговора в проверяемое ТЗ

Хакатонный MVP для кейса №3. Аналитик превращает встречу с заказчиком в требования, проверяет источники и передаёт команде структурированный документ. Основной интерфейс на русском; регистрация и API-ключ для демонстрации не нужны.

## Что умеет

### Рабочий MVP за 24 часа

**Проверенный реальный AI-путь: аудио → транскрипция → требования.** Для кейса «Из разговора в ТЗ» за 24 часа собран полный вертикальный сценарий: Yandex SpeechKit распознаёт короткую запись, YandexGPT формирует требования, роли и критерии приёмки, аналитик проверяет источники, редактирует результат и экспортирует документ. Путь проверен на реальной короткой записи; демонстрационные данные доступны отдельно.

**Ограничение демо: до 30 секунд и 1 МБ.** Поддерживаются WAV PCM 16-bit mono и OggOpus mono. Это техническое ограничение текущего MVP, а не финальный продуктовый лимит. Фокус 24 часов — работающий путь от аудио до проверяемого ТЗ без имитации обработки длинных файлов.

**Уже работает:** импорт готовой транскрипции, реальная расшифровка короткого аудио через SpeechKit, анализ требований через YandexGPT, ручная правка требований, источники и критерии приёмки, экспорт JSON, текста в Markdown, DOCX и печать в PDF.

**Что дальше:** встречи на 30–90 минут через асинхронный SpeechKit, Object Storage для больших файлов, очередь задач и фоновый worker со статусами и уведомлениями; роли в команде, совместная работа и интеграции с Telegram, VK и Max. Эти возможности запланированы, но ещё не реализованы. Подробнее — [roadmap](docs/ROADMAP.md).

### Возможности текущей версии

- **След требования:** точные реплики, говорящие, интервалы и объяснение классификации. Переход к сегменту, перемотка приложенной записи, воспроизведение отрывка и ручная перепривязка.
- **Рабочее пространство:** транскрипция, CRUD требований, роли, сценарии, вопросы, конфликт 14/30 дней, фильтры, группировка и массовая смена статуса.
- **Quality Gate:** прозрачная формула комплектности; показатели пересчитываются после правок. Это не оценка точности AI.
- **Локальная работа:** проекты и правки сохраняются в браузере, текст/SRT/VTT разбираются без сети. Записи воспроизводятся локально без подмены результатами демо.
- **Экспорт:** Markdown, JSON, DOCX, печать/PDF и передача краткой сводки. Экспорт содержит критерии и матрицу трассировки.

## Быстро открыть демо

Требуется Node.js 22.12+ (проверено на Node 24) и npm.

```sh
npm ci
npm run dev
```

Откройте адрес из терминала (обычно `http://127.0.0.1:5173`) и нажмите **Открыть демо за 30 секунд**. Получите учебную встречу о бронировании переговорных: 28 сегментов на 7:54, 18 элементов, две роли, три сценария, три вопроса и один конфликт. Материалы подготовлены заранее; аудиозапись в демо не включена. После первой загрузки production-версии оболочка доступна офлайн через service worker.

**Отдельный WAV** нужен для проверки реального пути: загрузка аудио → SpeechKit → анализ YandexGPT.

## Работа со своими материалами

Создайте проект или перетащите файл на главную. TXT/MD или вставленный текст разбиваются по непустым строкам; формат `Заказчик: реплика` сохраняет имя говорящего. SRT/VTT сохраняют таймкоды. Локальный анализатор выделяет явные маркеры («нужно», «нельзя», «договорились», «вопрос»), ставит низкую уверенность и необходимость проверки. Он не заявляет понимание контекста, извлечение ролей или обнаружение всех противоречий.

Медиа без AI остаётся локальным файлом для плеера. Добавьте готовую транскрипцию, чтобы получить черновик. Ограничения: медиа до 100 МБ, текст до 512 КБ и 180 000 символов. Время в обычном тексте приблизительное и не используется для точной синхронизации с записью. После перезагрузки выберите запись снова: большие Blob не сохраняются в localStorage.

## Реальный облачный режим: Yandex SpeechKit + Yandex AI Studio

Скопируйте `.env.example` в `.env`, заполните серверные переменные и запустите во втором терминале:

```sh
npm run dev:api
```

Vite перенаправляет `/api/*` на локальный сервер `127.0.0.1:3001`. Нажмите **AI-обработка** и подтвердите отправку материалов. Сам `npm run dev` запускает полностью рабочий локальный режим; сервер без ключа возвращает понятную ошибку 503.

| Переменная                   | Назначение                                                                                        |
| ---------------------------- | ------------------------------------------------------------------------------------------------- |
| `YANDEX_API_KEY`             | API-ключ сервисного аккаунта Yandex; только на сервере                                            |
| `YANDEX_FOLDER_ID`           | Каталог для анализа YandexGPT; для SpeechKit с API-ключом не передаётся                           |
| `YANDEX_ANALYSIS_MODEL_URI`  | Необязательно: URI модели, по умолчанию `gpt://<YANDEX_FOLDER_ID>/yandexgpt/latest`               |
| `YANDEX_SPEECHKIT_LANGUAGE`  | Язык распознавания, по умолчанию `ru-RU`                                                          |
| `YANDEX_SPEECHKIT_TOPIC`     | Тема распознавания, по умолчанию `general`                                                        |
| `YANDEX_TIMEOUT_MS`          | Таймаут одного запроса: 1000–55000 мс, по умолчанию 55000                                         |
| `YANDEX_ANALYSIS_MAX_TOKENS` | Лимит ответа анализа: 256–16000, по умолчанию 8000; учитывайте ограничения выбранной модели       |
| `APP_ORIGIN`                 | Необязательный точный origin опубликованного фронтенда для проверки источника браузерного запроса |
| `VITE_BASE_PATH`             | Публичный путь статических ресурсов, например `/specflow-hackathon/` для Pages; не секрет         |

Ключ никогда не помещается в `VITE_*`, исходники или git. `.env` и его варианты игнорируются; `.env.example` содержит только пустые поля и безопасные значения. Секрет задаётся в окружении серверного процесса. Для распознавания сервисному аккаунту нужны права SpeechKit; для анализа — права на генерацию текста в выбранном каталоге. Настройка аккаунта и ключа описана в [аутентификации SpeechKit](https://aistudio.yandex.ru/ru/docs/speechkit/concepts/auth) и [аутентификации AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/api-ref/authentication).

Реальные запросы выполняются серверным `fetch` к нативным REST API Yandex: SpeechKit v1 для распознавания и YandexGPT для анализа требований. OpenAI API, SDK и автоматического переключения на другой сервис нет. Запросы содержат `x-data-logging-enabled: false`; сырые ошибки провайдера и заголовки авторизации не возвращаются браузеру. Транскрипция считается недоверенными данными. Сервер проверяет JSON, структуру и ссылки и делает один повтор при некорректном ответе анализа. Каждый AI-элемент остаётся черновиком.

Синхронный режим принимает **до 30 секунд и 1 000 000 байт, один канал**: WAV PCM 16-bit с частотой 8/16/48 кГц либо OggOpus. Сервер проверяет контейнер и длительность, снимает WAV-заголовок перед отправкой PCM. MP3/MP4/M4A/WEBM/MOV остаются локальными вложениями; для облачного распознавания преобразуйте их в поддерживаемый формат или добавьте текст/SRT/VTT. Автоматической конвертации и обрезки нет. Ограничения и формат ответа: [SpeechKit v1](https://aistudio.yandex.ru/ru/docs/speechkit/stt/api/request-api).

SpeechKit v1 возвращает текст без таймкодов слов и разделения говорящих. Поэтому результат — один сегмент на длительность файла с именем «Участник» и отметкой приблизительного времени. Он не используется для точной перемотки к фразе. Демо и импорт SRT/VTT сохраняют свои таймкоды. Успешная транскрипция сохраняется до анализа: при ошибке YandexGPT её можно использовать локально или повторить только анализ.

Длинный или большой файл получает `413 ASYNC_REQUIRED` до обращения к Yandex. Фоновая обработка **ещё не подключена**: сервер не создаёт фиктивную задачу и не показывает выдуманный прогресс. Подготовлены контракт `AsyncTranscriptionProvider`, состояния `TranscriptionJob` и ответ `501 ASYNC_NOT_CONFIGURED` на `mode: "async"`. План подключения Object Storage и очереди — [ASYNC_TRANSCRIPTION](docs/ASYNC_TRANSCRIPTION.md).

Ошибки различают отсутствие настройки, отказ в доступе, квоту, таймаут, неподдерживаемый/повреждённый файл, отсутствие речи и неверный ответ. Нативный формат анализа сверён с [TextGeneration/completion](https://aistudio.yandex.ru/ru/docs/ai-studio/text-generation/api-ref/TextGeneration/completion); управление логированием — с [документацией AI Studio](https://aistudio.yandex.ru/en/docs/ai-studio/operations/disable-logging). Реальный путь проверен на короткой записи; для опубликованной версии серверные переменные Yandex настраиваются отдельно.

## Архитектура

React + TypeScript + Vite, React Router (hash-маршруты), Tailwind CSS и собственные доступные компоненты. UI работает с доменной моделью и чистым reducer. Общие Zod-схемы проверяют файлы, сохранённые проекты и ответы AI. Quality Gate и экспорт не зависят от интерфейса. Native dialog управляет фокусом; на телефоне зоны переключаются нижней навигацией.

`TranscriptionProvider`, `RequirementsExtractionProvider` и `ProjectRepository` отделяют внешние сервисы от домена. Сейчас проекты сохраняются в versioned localStorage, медиа — только в памяти вкладки. При удалении очищаются связи, есть отмена до следующего изменения и история последних 30 действий. Повреждённое хранилище не перезаписывается молча; экран восстановления позволяет скачать исходные данные. Подробности и диаграмма — [ARCHITECTURE](docs/ARCHITECTURE.md).

## Ограничения

- Нет регистрации, общей серверной БД, совместного редактирования и синхронизации между устройствами. Ссылка на локальный проект не открывает его на другом устройстве; передавайте сводку или экспорт.
- Источники проверяются структурно, но соответствие смысла требует человека. Confidence и Quality Gate не заменяют измеренные метрики качества.
- Сохранение ограничено квотой браузера. Нет универсального импорта JSON-экспорта обратно в интерфейс и миграции неизвестных будущих схем.
- Нет очереди, диаризации и обработки многочасовых записей. Отмена на клиенте прекращает ожидание, но не гарантирует отмену уже начатой платной работы провайдера.
- Реальное распознавание и анализ проверены на короткой записи. Это подтверждает работу интеграции, но не заменяет оценку качества на корпусе встреч. Автоматические тесты подменяют `fetch` Yandex и проверяют контракт и ошибки.
- Публичный AI-endpoint не имеет пользовательской авторизации. Для публикации AI включите защиту доступа платформы и бюджетные ограничения. Проверка origin не заменяет авторизацию. Статическое демо ключа не содержит.
- В браузерах без WebMCP работает обычный интерфейс. Опциональный read-only инструмент возвращает текущий проект; полноценная проверка в браузере с нативным WebMCP зависит от его поддержки.
